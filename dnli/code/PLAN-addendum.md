## A1（2026-10-13）codex 连不上服务端的调用判 call_error，不作废会话

- 发现：正式运行 13:32 起的 codex 会话中，多次调用连不上服务端（stderr：`workspace routing discovery failed`；returncode=1；日志里没有任何采样记录、没有回答、没有工具、没有输出文件）。完整性检查把这些「什么都没发生」的缺项判成 `check_failed`，按规则作废了整个会话（242 个已完成 unit 失效）。
- 规则：`codex_subject.is_no_contact()`——非零退出、无额度迹象、日志采样数为 0、没有任何回答与工具、没有未知事件或坏行、完整性错误全属「缺少某记录」一类——判 `call_error`（原因 `no_contact`）：不纳入、停下、**会话不作废**，由启动脚本续跑时重做。只要有任何回答、工具迹象，或指令来源改变，照原规则。
- 依据：没有产出就没有可纳入的内容，也没有可被污染的内容；作废会话的用意（防止隐藏的工具使用或环境改变影响已纳入的结果）在这种情况下不适用。
- 影响：`codex_subject.py` 进了 codex 的指纹，所以 **codex 的开发集与正式集在新指纹下重跑**；本地两个配置的指纹不受影响，正式运行照常。旧的 codex 结果移入 `raw/codex_v071/` 存档。
